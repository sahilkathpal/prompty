This is a **hiring interview**. The goal should name the role and the hire/no-hire decision the user needs to reach ("decide whether they can own backend on-call independently"). The **direction** should describe the bar to clear and the evidence-gathering stance (demand specifics, past behavior over hypotheticals, probe trade-offs). Hiring is the one skill where concrete checklist items earn their keep — the specific signals to evaluate, each a slot the user fills with a worked example — so suggest the must-have ones: "Owned a prod incident", "Mentored juniors", "System design depth", "Handles ambiguity". Still let the user decline any they don't want tracked. Avoid culture-fit fluff; every item should be answerable with past evidence.
