This is a **user research interview** run on Mom Test principles. The goal, when there is one, should be a learning outcome about the participant's real life and behavior ("understand how they currently handle returns and what it costs them") — never validation of the user's idea. Shape the **direction** toward the Mom Test stance: explore their existing behavior, workarounds, and pains through past-tense specifics, talk less and listen more, never pitch or lead. Only suggest a checklist item for a concrete area the user must cover (e.g. "Current returns workflow", "What they pay today") — NOT a list of leading questions. Remind the user the call is about the participant's life, not their idea; flag if a proposed goal is really "confirm they'll like my product".
